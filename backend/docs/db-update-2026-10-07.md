# DB 수정본 비교: 2026-10-07

비교 자료: 기존 `recruitment_db.sql`과 새 `recruitment_db (1).sql`.
첨부 원본 파일은 수정하지 않았습니다.

## 현재 백엔드 영향

7개 테이블의 이름, 컬럼, 타입, 외래키와 출석 중복 제약은 같습니다.
SQL 설명 주석이 제거되었고 샘플 데이터 보완이 추가되었습니다.
현재 사용하는 `Users`, `Posts` 모델과 로그인/조회 API에는 코드 변경이 필요하지 않습니다.
프론트엔드의 API 경로, 응답 형식, 로그인 토큰 방식도 같습니다.
모집글 API는 DB의 `current_size`와 `status`를 그대로 반환합니다.

## 변경된 데이터

`ApprovedMembers`에 승인된 지원서와 연결된 두 행을 추가했습니다.

| 모집글 ID | 팀원 학번 | 지원서 ID |
| --- | --- | --- |
| 1 | 20191003 | 2 |
| 5 | 20201015 | 5 |

전체 모집글의 현재 인원을 `1 + 승인된 팀원 수`로 다시 계산합니다. 작성자 한 명을 포함합니다.

| 모집글 ID | 이전 현재 인원 | 수정 후 현재 인원 | 목표 인원 | 수정 후 상태 |
| --- | --- | --- | --- | --- |
| 1 | 1 | 2 | 4 | RECRUITING |
| 2 | 2 | 1 | 5 | RECRUITING |
| 3 | 3 | 1 | 3 | CLOSED |
| 4 | 1 | 1 | 4 | RECRUITING |
| 5 | 1 | 2 | 2 | RECRUITING |

기존 2번/3번 글의 현재 인원은 승인 팀원 데이터와 맞지 않았습니다.
수정본은 실제 ApprovedMembers 행에 맞춰 계산하므로 두 글의 현재 인원이 내려갑니다.

## DB 담당자와 남은 확인 사항

- 5번 글은 정원이 찼지만 상태가 `RECRUITING`입니다. 정원 도달 시 자동 마감 정책을 적용하려면 `CLOSED`로 맞춰야 합니다.
- 3번 글은 인원이 줄어도 `CLOSED`를 유지합니다. 팀장이 수동 마감한 글로 처리할 수 있으므로 인원이 줄었다는 이유만으로 다시 열지 않습니다.
- 비밀번호는 여전히 평문입니다. 로그인 전에 `python -m scripts.hash_seed_passwords --apply`가 필요합니다.
- `Applications(post_id, applicant_id)`와 `ApprovedMembers(post_id, member_id)` 중복 방지 UNIQUE 제약은 아직 없습니다.
- 기술 스택/프로필 필드는 아직 없습니다. 해당 기능 구현 전에 스키마를 함께 정해야 합니다.

새 SQL에는 DROP TABLE이 포함되어 있습니다. 이미 데이터가 있는 DB를 갱신할 때에는 DB 담당자가 데이터 보존용 변경 SQL을 따로 준비해야 합니다.
실제 DB에 새 SQL을 자동 적용하지 않았습니다.
