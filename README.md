# StudyMate 프론트엔드

HTML, CSS, JavaScript를 사용합니다.
회원가입, 로그인/갱신/로그아웃, 내 정보, 모집글 작성/조회/수정/삭제/마감을 백엔드에 연결했습니다.
지원/승인/거절, 내 활동, 출석 관리/인증/이력과 ESP32 장치 등록까지 서버 API에 연결했습니다. 로컬 데모는 별도로 유지합니다.

## 파일별 역할

| 파일 | 내용 |
| --- | --- |
| `index.html` | 모집글 목록과 검색 |

| `profile.html` | 로그인한 사용자 정보 |
| `recruit-write.html`, `recruit-detail.html` | 모집글 작성/수정, 상세 |
| `apply.html`, `applicants.html` | 지원서 작성, 지원자 관리 |
| `my-applications.html`, `my-teams.html` | 내 지원 현황, 참여 중인 팀 |
| `attendance.html`, `attendance-check.html` | 팀장 출석 관리, 팀원 코드 입력 |
| `attendance-history.html` | 회차별 출석 기록 |
| `lcd-simulator.html` | ESP32 연결 전 코드 표시 테스트 |
| `js/app.js` | 화면 구성, 폼 처리, 메뉴 |
| `js/server.js` | 백엔드 API 요청, 서버 로그인, 모드 전환 |

| `css/style.css`, `css/app.css` | 공통 스타일과 반응형 화면 |

## 1. 실행

VS Code에서 프로젝트 폴더를 열고 Live Server로 `index.html`을 실행합니다.
포트는 **5500**을 사용합니다.

Python이 설치되어 있으면 프로젝트 폴더의 터미널에서 실행해도 됩니다.

```powershell
python -m http.server 5500 --bind 127.0.0.1
```

접속 주소: http://127.0.0.1:5500

현재 백엔드는 5500번 프론트 주소를 CORS에 허용하고 있습니다.
다른 포트나 배포 주소를 사용하면 백엔드의 `CORS_ORIGINS`에도 해당 주소를 추가해야 합니다.
HTML 파일을 직접 여는 대신 Live Server나 위 명령으로 실행하세요.

## 2. 서버 연결

- 서버: https://swe-project-u3f0.onrender.com
- API 문서: https://swe-project-u3f0.onrender.com/docs
- API 기본 주소는 `js/server.js`의 `BASE`에서 설정합니다.

| 메서드 | 주소 | 연결한 기능 |
| --- | --- | --- |
| POST | `/api/auth/login` | 로그인 |
| GET | `/api/users/me` | 내 정보 |
| GET | `/api/posts` | 목록, 검색, 필터, 페이지 이동 |
| GET | `/api/posts/{post_id}` | 상세 조회 |
| POST | `/api/auth/signup` | 회원가입 |
| POST | `/api/auth/refresh` | 토큰 갱신 |
| POST | `/api/auth/logout` | 서버 로그아웃 |
| POST | `/api/posts` | 모집글 작성 |
| PATCH / DELETE | `/api/posts/{post_id}` | 수정 / 삭제 |
| POST | `/api/posts/{post_id}/close` | 모집 마감 |
| GET | `/api/posts/{post_id}/context` | 작성자 여부, 내 지원 상태 |
| POST / GET | `/api/posts/{post_id}/applications` | 지원 / 지원자 목록 |
| PATCH | `/api/applications/{application_id}` | 승인 / 거절 |
| GET | `/api/users/me/applications` | 내 지원 현황 |
| GET | `/api/users/me/teams` | 내 팀 |

로그인은 JSON으로 아이디와 비밀번호를 전송합니다.
비밀번호는 저장하지 않고 접근/갱신 토큰과 사용자 정보를 sessionStorage에 보관합니다.
보호된 API에만 Bearer 헤더를 붙입니다. 만료나 401이 발생하면 갱신을 한 번 시도하고 토큰을 둘 다 교체합니다.
동시에 들어오는 요청은 같은 갱신 결과를 기다립니다. 갱신 실패 시 저장 정보를 지우고 재로그인을 안내합니다.
갱신 토큰이 복사되지 않도록 로그인된 탭을 복제하지 말고, 새 탭은 별도로 로그인해 주세요.
로그아웃은 서버에 세션 취소를 요청한 후 브라우저 토큰을 지웁니다. 통신 실패 시 오류를 표시하고 다시 시도할 수 있습니다.

서버 회원가입 후 로그인할 수 있습니다. 비밀번호 확인 값은 브라우저에서만 비교합니다.
수정/삭제 버튼은 공개 작성자 이름이 아닌 context API의 is_owner로 판단합니다.
서버 403/409 오류는 권한·중복·정원·처리 상태 안내를 표시합니다.

### 배포 상태 (2026-11-02 확인)

Render API 버전은 0.4.0입니다. 이전에 배포 대기였던 지원/승인/내 활동과 출석/장치 API를 확인했습니다.
출석 API가 없는 서버에 연결하면 해당 페이지에 배포 대기 안내가 나옵니다.
백엔드와 firmware 폴더는 참고만 했고 수정하지 않았습니다.

검색은 제목/내용의 키워드, 모집 분야, 모집 상태를 사용합니다.
분야는 `Web/Frontend`처럼 정확한 값으로 검색합니다.
목록은 한 페이지에 6개씩 표시하며, 인원과 모집 상태는 서버 응답을 그대로 표시합니다.
로딩, 빈 결과, 요청 실패, 재시도도 처리했습니다.

## 3. 로컬 테스트

처음에는 서버 연결 모드로 실행됩니다.
상단의 **로컬 데모로 전환**을 누르면 아직 API가 없는 기능을 확인할 수 있습니다.

1. 팀장 계정으로 회원가입하고 모집글을 작성합니다.
2. 다른 계정으로 로그인해서 지원합니다.
3. 팀장이 지원자 관리에서 승인하거나 거절합니다.
4. 내 팀에서 출석 관리로 이동해 LCD 시뮬레이터를 연결하고 출석을 시작합니다.
5. 시뮬레이터에서 코드를 확인하고 표시 확인 버튼을 누릅니다.
6. 승인된 팀원이 코드를 입력하면 팀장 화면과 출석 이력에 반영됩니다.

팀 정원은 팀장을 포함합니다. 정원 도달 시 모집이 자동 마감됩니다.
현재 로컬 구현에서는 승인/거절 후 변경과 재모집은 지원하지 않습니다.
출석은 5분이며 회차별로 기록을 남깁니다. 실제 ESP32는 아직 연결하지 않았습니다.

서버와 로컬은 계정과 데이터를 따로 사용합니다.
로컬 데이터는 같은 브라우저에서만 공유되고 다른 기기에서는 볼 수 없습니다.
로그인은 탭별로 유지됩니다. 새 탭을 복제했다면 현재 로그인한 계정을 확인하세요.
로컬 비밀번호는 해시로 저장하지만, 실제 권한 검증은 추후 백엔드에서 처리해야 합니다.

저장 키는 `studymate.db.v2`입니다.
이전 버전에서 사용한 localStorage 값은 삭제하거나 자동으로 옮기지 않습니다.

## 4. 서버 출석과 ESP32

1. 팀장으로 로그인하고 내 팀 → 출석 관리로 이동합니다.
2. 등록된 장치가 없으면 ‘새 ESP32 장치 등록’을 누릅니다. 기존 장치 ID/키를 보관하고 있다면 재등록하지 않습니다.
3. 발급된 장치 ID와 인증키를 펌웨어의 로컬 config.h에 입력합니다. 키는 처음 한 번만 확인할 수 있고 프론트 저장소에는 보관하지 않습니다. 페이지를 나가면 다시 표시할 수 없습니다.
4. Wi-Fi 설정과 API 주소를 입력하고 펌웨어를 보드에 업로드합니다. 설정·배선·Arduino IDE 절차는 백엔드 저장소의 firmware/README.md를 따릅니다.
5. 팀장이 연결된 장치를 선택하고 출석을 시작합니다. 서버가 만든 코드를 ESP32가 받아 LCD에 표시합니다.
6. 화면의 ‘LCD 표시 확인됨’은 기기가 보낸 ACK입니다. 프론트가 코드를 표시하거나 ACK를 대신 보내지 않습니다.
7. 승인된 팀원은 내 팀 → 출석 인증에서 LCD의 숫자 6자리를 입력합니다. 앞자리 0도 그대로 입력합니다.
8. 팀장은 명단을 확인하고 종료합니다. 회차별/개인별 기록은 출석 이력에서 조회합니다.

출석은 시작부터 5분입니다. 팀장은 인증 대상에서 제외됩니다.
같은 팀의 활성 회차는 하나이며 마감된 팀에서도 시작할 수 있습니다.
현황은 화면이 열려 있을 때 3초 간격으로 조회합니다. 미인증 팀원은 종료 후 결석으로 표시합니다.
잘못된 코드, 만료, 권한 없음, 요청 제한(분당 5회)은 오류로 안내합니다. 최종 판정은 서버가 합니다.
장치 키와 Wi-Fi 비밀번호는 채팅/스크린샷/공개 GitHub에 포함하지 마세요.
실제 LCD 출력과 자동 ACK는 ESP32/LCD에서 별도 확인해야 합니다. 이 프론트 변경으로 보드에 펌웨어가 업로드되지는 않습니다.

### 남은 작업

- 테스트 팀에서 회원가입부터 지원/승인/출석까지 실제 저장 흐름 확인
- ESP32 Wi-Fi/LCD 표시/자동 ACK/만료/재연결을 실기기로 확인
- 모바일과 오류 상황 확인, 최종 배포 후 로컬 데모 정리
- 기술 스택 프로필/필터는 DB/API 범위를 팀과 확정

## 5. 테스트

Node.js가 설치된 환경에서 실행합니다.

```powershell
node tests/data.test.cjs
node tests/server.test.cjs
node tests/extensions.test.cjs
node tests/attendance-server.test.cjs
```

로컬 테스트는 고유 ID, 권한, 중복 지원, 정원, 출석 만료와 기록 삭제를 확인합니다.
API 테스트는 모의 응답으로 로그인, 토큰, 검색 조건, 오류 처리, 서버/로컬 분리를 확인합니다.
두 테스트는 실제 서버 DB를 변경하지 않습니다.

브라우저에서는 서버 테스트 계정으로 로그인, 내 정보, 새로고침 후 로그인 유지,
로그아웃, 잘못된 비밀번호 안내, 모집글 목록/상세와 검색을 확인했습니다.

추가 계약 테스트는 회원가입 본문, 글 작성/수정, 지원 요청, 403/409, 동시 토큰 갱신, 갱신 응답 유실, 서버 로그아웃을 모의 응답으로 확인합니다. 실제 계정 생성이나 기존 글 수정/삭제를 자동 실행하지 않습니다.

2026-10-30 브라우저 확인: 서버 로그인, context 기반 작성자 버튼, 기존 글 수정 폼의 값 조회, 0.3.0 미배포 안내, 서버 로그아웃을 확인했습니다. 기존 모집글은 수정·삭제하지 않았습니다.

출석 계약 테스트는 장치 키 비저장, 일반 회차의 코드 비노출, 6자리 문자열, 명단 조회와 400/403/409/429 안내를 확인합니다. 실제 장치 등록·출석 시작·기록 생성은 자동 테스트에서 수행하지 않습니다.

2026-11-02 실제 브라우저에서는 기존 테스트 계정의 내 팀, 장치 목록, 출석 관리와 빈 이력 조회를 확인했습니다. 실제 장치 등록·출석 시작·팀원 인증은 실행하지 않았으며 LCD/ACK 실기기 검증은 남아 있습니다.
