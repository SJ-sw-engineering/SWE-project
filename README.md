# StudyMate 프론트엔드

HTML, CSS, JavaScript를 사용합니다.
현재 로그인, 내 정보, 모집글 목록/상세 조회와 검색을 백엔드에 연결했습니다.
회원가입, 모집글 작성/수정/삭제, 지원/승인, 출석은 localStorage로 동작하며 API가 추가되면 연결할 예정입니다.

## 파일별 역할

| 파일 | 내용 |
| --- | --- |
| `index.html` | 모집글 목록과 검색 |
| `login.html`, `signup.html` | 로그인, 로컬 회원가입 |
| `profile.html` | 로그인한 사용자 정보 |
| `recruit-write.html`, `recruit-detail.html` | 모집글 작성/수정, 상세 |
| `apply.html`, `applicants.html` | 지원서 작성, 지원자 관리 |
| `my-applications.html`, `my-teams.html` | 내 지원 현황, 참여 중인 팀 |
| `attendance.html`, `attendance-check.html` | 팀장 출석 관리, 팀원 코드 입력 |
| `attendance-history.html` | 회차별 출석 기록 |
| `lcd-simulator.html` | ESP32 연결 전 코드 표시 테스트 |
| `js/app.js` | 화면 구성, 폼 처리, 메뉴 |
| `js/server.js` | 백엔드 API 요청, 서버 로그인, 모드 전환 |
| `js/data.js` | localStorage 데이터 처리 |
| `css/style.css`, `css/app.css` | 공통 스타일과 반응형 화면 |
| `tests/` | 데이터 처리와 API 연동 테스트 |

## 1. 실행

VS Code에서 프로젝트 폴더를 열고 Live Server로 `index.html`을 실행합니다.
포트는 **5500**을 사용합니다.

Python이 설치되어 있으면 프로젝트 폴더의 터미널에서 실행해도 됩니다.

```powershell
python -m http.server 5500 --bind 127.0.0.1
```

접속 주소: http://127.0.0.1:5500

현재 백엔드는 5500번 프론트 주소를 CORS에 허용하고 있습니다.
다른 포트나 배포 주소를 사용하면 백엔드의 `CORS_ORIGINS`에도 해당 주소를 추가해야 합니다.
HTML 파일을 직접 여는 대신 Live Server나 위 명령으로 실행하세요.

## 2. 서버 연결

- 서버: https://swe-project-u3f0.onrender.com
- API 문서: https://swe-project-u3f0.onrender.com/docs
- API 기본 주소는 `js/server.js`의 `BASE`에서 설정합니다.

| 메서드 | 주소 | 연결한 기능 |
| --- | --- | --- |
| POST | `/api/auth/login` | 로그인 |
| GET | `/api/users/me` | 내 정보 |
| GET | `/api/posts` | 목록, 검색, 필터, 페이지 이동 |
| GET | `/api/posts/{post_id}` | 상세 조회 |

로그인은 JSON으로 아이디와 비밀번호를 전송합니다.
내 정보 요청에는 `Authorization: Bearer 토큰`을 붙입니다.
비밀번호는 저장하지 않고, 토큰과 사용자 정보는 sessionStorage에 보관합니다.
새로고침 시 사용자 정보를 다시 조회하며 토큰 만료나 401 응답이 발생하면 재로그인을 안내합니다.
로그아웃은 해당 탭에 저장한 토큰을 제거합니다. 현재 백엔드에는 토큰 갱신과 서버 측 로그아웃 API가 없습니다.

서버 회원가입은 아직 지원하지 않습니다. 로그인할 계정은 백엔드 담당자에게 확인하세요.
로컬에서 가입한 계정으로 서버에 로그인할 수는 없습니다.

검색은 제목/내용의 키워드, 모집 분야, 모집 상태를 사용합니다.
분야는 `Web/Frontend`처럼 정확한 값으로 검색합니다.
목록은 한 페이지에 6개씩 표시하며, 인원과 모집 상태는 서버 응답을 그대로 표시합니다.
로딩, 빈 결과, 요청 실패, 재시도도 처리했습니다.

## 3. 로컬 테스트

처음에는 서버 연결 모드로 실행됩니다.
상단의 **로컬 데모로 전환**을 누르면 아직 API가 없는 기능을 확인할 수 있습니다.

1. 팀장 계정으로 회원가입하고 모집글을 작성합니다.
2. 다른 계정으로 로그인해서 지원합니다.
3. 팀장이 지원자 관리에서 승인하거나 거절합니다.
4. 내 팀에서 출석 관리로 이동해 LCD 시뮬레이터를 연결하고 출석을 시작합니다.
5. 시뮬레이터에서 코드를 확인하고 표시 확인 버튼을 누릅니다.
6. 승인된 팀원이 코드를 입력하면 팀장 화면과 출석 이력에 반영됩니다.

팀 정원은 팀장을 포함합니다. 정원 도달 시 모집이 자동 마감됩니다.
현재 로컬 구현에서는 승인/거절 후 변경과 재모집은 지원하지 않습니다.
출석은 5분이며 회차별로 기록을 남깁니다. 실제 ESP32는 아직 연결하지 않았습니다.

서버와 로컬은 계정과 데이터를 따로 사용합니다.
로컬 데이터는 같은 브라우저에서만 공유되고 다른 기기에서는 볼 수 없습니다.
로그인은 탭별로 유지됩니다. 새 탭을 복제했다면 현재 로그인한 계정을 확인하세요.
로컬 비밀번호는 해시로 저장하지만, 실제 권한 검증은 추후 백엔드에서 처리해야 합니다.

저장 키는 `studymate.db.v2`입니다.
이전 버전에서 사용한 localStorage 값은 삭제하거나 자동으로 옮기지 않습니다.

## 4. 다음 작업

1. 모집글 작성/수정/삭제와 수동 마감 API 연결
2. 지원, 승인/거절, 내 지원 현황과 내 팀 API 연결
3. 회원가입 API 연결
4. 출석 시작/종료, 코드 인증, 출석 이력 API 연결
5. ESP32/LCD 표시 상태 연결 후 시뮬레이터 정리
6. 전체 기능 테스트 후 로컬 모드 제거

추가 API의 경로와 요청/응답 형식은 백엔드 담당자와 맞춰서 연결합니다.
공개 모집글 응답에는 작성자 아이디와 지원자 수가 없어서 서버 화면에는 표시하지 않습니다.
현재 DB에 없는 마감일, 기술 스택 프로필, 역할 필터는 스키마와 API가 정해진 뒤 추가해야 합니다.

## 5. 테스트

Node.js가 설치된 환경에서 실행합니다.

```powershell
node tests/data.test.cjs
node tests/server.test.cjs
```

로컬 테스트는 고유 ID, 권한, 중복 지원, 정원, 출석 만료와 기록 삭제를 확인합니다.
API 테스트는 모의 응답으로 로그인, 토큰, 검색 조건, 오류 처리, 서버/로컬 분리를 확인합니다.
두 테스트는 실제 서버 DB를 변경하지 않습니다.

브라우저에서는 서버 테스트 계정으로 로그인, 내 정보, 새로고침 후 로그인 유지,
로그아웃, 잘못된 비밀번호 안내, 모집글 목록/상세와 검색을 확인했습니다.
